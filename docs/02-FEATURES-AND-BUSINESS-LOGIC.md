## 1. Autentikasi

- `/login` (`resources/views/auth/login.blade.php`): satu kolom **"Email atau Nama"** (`name="login"`) + Password, tombol "Masuk ✨", desain pastel pink; pesan error Bahasa Indonesia.
- **Login dengan email ATAU nama** (`AuthController@login`): bila isian berformat email → `Auth::attempt(['email'=>…])`; selain itu dicari akun dengan `users.name` yang sama (MySQL tidak membedakan huruf besar/kecil) dan dicoba lewat emailnya. Nama tidak unik, jadi bila ada beberapa akun bernama sama, semuanya dicoba satu per satu sampai password cocok. Gagal → "Email/nama atau password belum cocok. Coba cek lagi ya 💕" (error key `login`).
- `Auth::attempt(..., true)` → **remember = true default**; sesi 1 tahun (`SESSION_LIFETIME=525600`). Berhasil → `redirect()->intended('/')`.
- Sudah login lalu membuka `/login` → middleware `guest` mengarahkan ke `/`. Belum login mengakses halaman lain → redirect ke `/login`.
- Halaman login **selalu load penuh** (bukan Turbo): `<meta name="turbo-visit-control" content="reload">` + `data-turbo="false"` pada form, supaya token CSRF dan sesi baru terbaca bersih.

## 2. Master Alat Gym (`/alat`, `EquipmentController`)

- Tambah alat (nama + kategori via chips: Beban Bebas, Mesin Latihan, Kardio & Matras, Tanpa Alat); **toggle** ketersediaan (`is_available`) lewat **AJAX** (`api()` PATCH, controller membalas JSON bila `expectsJson`) sehingga halaman tidak reload dan posisi scroll tetap; tanpa JS/permintaan non-JSON controller tetap `back()` seperti biasa; hapus (modal konfirmasi lewat `data-confirm`). Ada juga tombol **Reset Semua Alat** di bagian bawah daftar (hanya tampil bila ada alat): form DELETE ke `alat.reset` dengan modal konfirmasi `data-confirm` bergaya bahaya, menghapus **seluruh** alat sekaligus agar daftar bisa diinput ulang dari 0; selama daftar kosong, program tidak bisa dibuat karena semua gerakan wajib beralat, jadi isi daftar alat dulu sebelum generate program.
- **Pencarian alat**: kotak cari di atas daftar menyaring baris alat secara langsung saat mengetik (JS halaman, tanpa reload), cocok terhadap nama alat atau nama kategorinya; grup kategori yang hasil saringannya kosong ikut disembunyikan, dan ada pesan kosong bila tidak ada yang cocok. Memudahkan mencari alat tertentu, misalnya saat mau mengunggah fotonya.
- **Foto alat (opsional)**: form tambah alat punya input file foto; tiap alat bisa tambah/ganti foto (tombol kamera, langsung unggah saat file dipilih) dan hapus foto (link "Hapus foto" di bawah status, pakai modal konfirmasi). Validasi: gambar JPG/PNG/WebP maks 4 MB, disimpan di disk `public` folder `equipments` (kolom `image_path`). Root disk `public` sengaja diarahkan ke folder asli `public/uploads` dengan awalan URL `/uploads` (lihat `config/filesystems.php`): awalan `/storage/*` diblokir 404 oleh snippet keamanan Caddyfile bersama di VPS, dan FrankenPHP juga tidak melayani file di balik symlink folder (`storage:link`). Baris alat menampilkan thumbnail 52px yang memuat **versi kecil** foto (`Equipment::thumbUrl()`, dibuat trait `HasThumb`: maks 480px JPEG q80 di subfolder `thumbs`, dibuat saat unggah/ganti dan untuk foto lama lewat backfill; file asli hanya dimuat saat thumbnail diklik untuk foto penuh di modal `#equipmentImageModal`). Media Gerakan memakai pola yang sama (`ExerciseMedia::thumbUrl()`, khusus gambar). Di sisi server, Caddy memberi `Cache-Control` untuk situs ini: `/css/*` dan `/js/*` 10 menit, `/uploads/*` 30 hari (nama file acak, berubah = URL baru), agar navigasi berulang tidak mengunduh ulang aset yang sama. Foto dipakai untuk ikon mata di modal Lihat Program dan di live session (lihat §3e dan §5); pemetaan nama alat → URL foto dibangun `Equipment::imageMap()` dan dikirim ke kedua halaman sebagai `EQUIPMENT_IMAGES`.
- **Media Gerakan (contoh cara melakukan gerakan)**: bagian di halaman Alat Gym (di bawah daftar alat) untuk mengelola contoh gerakan per **nama gerakan**. Form tambah menerima nama gerakan + file; daftarnya menampilkan semua nama gerakan yang dikenal (`ExerciseMedia::knownNames()`: dari program aktif semua klien + baris yang sudah ada), masing-masing dengan status sudah/belum ada media, tombol kamera untuk tambah/ganti (langsung unggah saat file dipilih), thumbnail yang bisa diklik untuk pratinjau penuh di modal `#exerciseMediaModal`, dan link hapus media (modal konfirmasi). Validasi: mp4/webm/mov/gif/jpg/png/webp maks **6 MB** (di bawah batas unggah server 8 MB), disimpan di disk `public` folder `gerakan` (kolom `media_path`); mengganti media menghapus file lama. Pencocokan ke gerakan program memakai `name_key` ternormalisasi (`ExerciseMedia::keyFor()` ≡ `mvKey()` di JS), jadi perbedaan huruf besar/kecil dan tanda hubung tidak masalah. Media dipakai untuk tombol putar di modal Lihat Program dan di live session (lihat §3e dan §5); pemetaan dibangun `ExerciseMedia::mediaMap()` dan dikirim ke kedua halaman sebagai `EXERCISE_MEDIA`. Kolom `credit` (atribusi sumber, mis. foto CC dari wger) ditampilkan kecil di bawah media pada modal. Daftar Gerakan punya **kotak pencariannya sendiri** (`#mvSearch`, menyaring langsung saat mengetik berdasarkan nama gerakan, terpisah dari pencarian alat `#eqSearch` yang hanya menyaring daftar alat; keduanya punya pesan kosong masing-masing).
- **Integrasi AI**: `AiWorkoutService::generate()` mengambil `Equipment::where('is_available', true)->pluck('name')` dan memasukkannya ke *system prompt* Gemini ("setiap gerakan HARUS memakai satu alat dari daftar berikut, tanpa kecuali"; gerakan bodyweight dilarang keras). Hasil AI disaring `matchedEquipment()` (lihat §4). Template cadangan juga hanya memakai alat yang tersedia (pencocokan kata kunci nama alat: `find()` memakai alat **pertama** yang namanya memuat kata kunci, bisa daftar kata kunci berurutan). Gunakan kata kunci yang spesifik (mis. `'lat pulldown'`, bukan `'lat'` yang ikut cocok dengan "Barbell & **Plate**"). Alat yang tidak ada → gerakan dilewati, tidak ada pengganti bodyweight.

## 3. Manajemen Klien (`/klien`, `ClientController`, `clients.blade.php`)

Daftar klien **terurut abjad nama** (`ClientController@index` memakai `orderBy('name')`) dan punya **kotak pencarian nama** (`#clientSearch`, menyaring langsung saat mengetik, ada pesan kosongnya). Kartu klien tampil **ringkas secara bawaan**: hanya avatar inisial, nama, nomor WA, dan chevron. Ketuk kepala kartu untuk membuka detail ke bawah (`.client-detail`, animasi grid 0fr→1fr, chevron berputar): tag (tujuan, tiap fokus tubuh, frekuensi, umur, lingkar perut), statistik (**Sisa sesi**, **Berat** + selisih dari log pertama, **Protein/hari** `min–max g`), catatan, dan tombol: **Lihat Program**, **History**, **BB**, **Paket**, **Edit Data**, **Hapus**. Tiap kartu bisa dibuka-tutup sendiri-sendiri.

### 3a. Tambah klien (wizard 3 langkah, modal `#wizardModal`)
1. Data diri: nama, nomor WA, gender (chips), berat, tinggi (opsional), **umur (wajib, 5–100 tahun; kolom `age`, ikut dikirim ke prompt AI agar program menyesuaikan usia)**, lingkar perut (opsional, hanya bila klien nyaman diukur). Langkah 2 juga punya kolom bebas **Alasan / tujuan khusus** (`goal_note`, opsional) untuk tujuan yang tidak ada di daftar chips, dan pilihan tujuan **Persiapan Lari / Marathon**.
2. Tujuan utama (chips), **fokus bagian tubuh (multi-select chips)**, frekuensi 1x/2x/3x, **tingkat keaktifan di luar sesi PT**, paket sesi, catatan.
3. Ringkasan: **rentang protein real-time** (`75g – 90g / hari`, "Batas minimal aman | Target optimal", panduan porsi ayam/telur/tempe untuk minimal & optimal) + info bahwa AI akan membuat program.

`store()`: validasi (pesan Indonesia) → `normalizeFocus()` → `calcProteinRange()` → `AiWorkoutService::generate()` → transaksi: buat klien, 1 `weight_logs`, dan program siklus 1 (`cycle_number = 1`, `is_active = true`) per sesi. Flash: "…dibuat dengan bantuan AI" atau "…dengan template gerakan".

### 3b. Kalkulator protein (logika)
Lihat `01-DATABASE-AND-MODELS.md` → "Rentang protein". Di form (klien baru **dan** edit) fungsi `renderProtein()` di `clients.blade.php` menghitung ulang saat berat, gender, tujuan, frekuensi, atau keaktifan berubah. Hasilnya identik dengan server (sudah diuji 864 kombinasi).

### 3c. Edit klien + generate ulang (modal `#editModal`, `ClientController@update`)
- Form terisi otomatis (data diambil dari atribut `data-client` pada tombol Edit). Semua field tersedia: nama, WA, gender, berat, tinggi, lingkar perut, sisa paket, catatan, tujuan, alasan/tujuan khusus, fokus (multi), frekuensi, keaktifan; rentang protein dihitung real-time.
- Kotak peringatan kuning (`.info-warn`): "⚠️ Info: Jika kamu mengedit … program gerakan AI klien akan dibuat ulang…".
- Dua tombol submit (`name="regenerate"`):
  - **Simpan Perubahan & Generate Gerakan Baru ✨** (`regenerate=1`): panggil AI (di luar transaksi), lalu dalam transaksi: program aktif lama → `is_active=false`, buat program baru dengan `cycle_number = max(cycle_number)+1`, dan **jadwal mendatang yang belum dimulai** (`status=scheduled`, `started_at null`, tanggal ≥ hari ini) dialihkan ke program baru secara bergilir (Sesi A, B, C…). Sesi `completed`/berjalan **tidak disentuh** → riwayat utuh.
  - **Simpan Data Saja** (`regenerate=0`): hanya update data; program tidak berubah.
- Jika berat berubah → ikut dicatat di `weight_logs`. Rentang protein dihitung ulang.
- Validasi gagal pada form edit: redirect balik dengan error di toast (input `_form=edit` mencegah modal wizard terbuka otomatis).

### 3d. Berat badan, paket, hapus
- **BB** (`updateWeight`): input berat baru, tampil riwayat dengan selisih; `weight_logs` bertambah; protein dihitung ulang.
- **Paket** (`addSessions`): `increment('remaining_sessions', n)`.
- **Hapus**: `data-confirm` modal; cascade ke program/jadwal/log.

### 3e. Lihat Program
Modal membaca `activePrograms` (dari atribut `data-client`) dan menampilkan tiap sesi dengan gerakan, set×rep, target kg, alat, tips. Bila alat suatu gerakan punya foto (`EQUIPMENT_IMAGES[equipment]` ada), di kanan baris gerakan tampil tombol ikon mata (`bi-eye`) yang membuka foto alat di modal `#equipmentImageModal`; tanpa foto, tombol tidak dirender. Bila gerakan itu sendiri punya contoh media (`EXERCISE_MEDIA[mvKey(nama gerakan)]` ada), di samping tombol mata tampil tombol ikon putar (`bi-play-circle`) yang membuka contoh gerakan di modal `#exerciseMediaModal` (video diputar otomatis tanpa suara dan muter/loop, GIF/gambar ditampilkan, plus baris atribusi `credit` bila ada); tanpa media, tombol tidak dirender. Menutup modal menghentikan video.
- **Ganti Gerakan** (tombol `Ganti` di tiap baris gerakan): mengganti SATU gerakan tanpa generate ulang. Membuka modal `#swapExerciseModal`: `GET /program/{program}/gerakan/{index}/alternatif` menampilkan gerakan sekarang + daftar alternatif dari `AiWorkoutService::alternativesFor()` (gerakan lain dari area otot yang sama menurut pustaka `buildLibrary()`, hanya yang beralat & alatnya tersedia, dan belum dipakai di sesi itu; area ditentukan dari nama gerakan di pustaka, atau dari label sesi bila nama tidak dikenal). Memilih satu mengirim `PATCH /program/{program}/gerakan/{index}` dengan nama pengganti; server memvalidasi nama itu memang ada di daftar alternatif, menukar entri itu saja di `exercises_json`, dan membalas gerakan baru + seluruh daftar. Modal program me-render ulang dari data terbaru dan atribut `data-client` tombol asal ikut diperbarui agar konsisten saat modal dibuka lagi.
- **Penentuan otot dari nama gerakan** (`AiWorkoutService::muscleAreaFor()`): area ditebak dari kata kunci nama gerakan (aturan berurutan, spesifik dulu: `romanian deadlift`→Bokong sebelum `deadlift`→Punggung; `leg curl`→Kaki sebelum `curl`→Lengan & Bahu; `squat`/`lunge`→Kaki; `chest press`/`bench press`/`pec`/`fly`→Dada; `pulldown`/`row`→Punggung; `crunch`/`twist`→Perut; dst), BUKAN dari daftar asal gerakan, jadi Squat di sesi Seluruh Tubuh diganti gerakan kaki, bukan Lat Pulldown. Cadangan: nama persis di pustaka → label sesi → Seluruh Tubuh.
- **Pengecualian Plank (gerakan berbasis waktu)**: satu-satunya gerakan tanpa alat yang boleh masuk program, dan hanya lewat pilihan manual pelatih: **Plank** (`timed => true`, alat "Tanpa Alat", target `3 x 45 detik`) ditawarkan di daftar Tambah Gerakan dan Ganti Gerakan khusus area **Perut & Pinggang** (`alternativesForArea()`/`alternativesFor()` menambahkan `timedExerciseEntry()`; `validateReplacement()` menerimanya lewat `asTimedExercise()`). Program otomatis (AI maupun template fallback) TIDAK pernah memuat Plank; aturan wajib beralat lainnya tetap penuh. Di sesi live, kartu Plank berisi baris set **Durasi (detik)** tanpa kolom beban, dan hasil tersimpan berlabel detik (lihat §5).
- **Atur urutan gerakan** (pegangan grip `bi-grip-vertical` di kiri tiap baris): seret baris ke atas/bawah di dalam sesinya (SortableJS via CDN, handle khusus grip agar tidak bentrok dengan tombol lain). Saat dilepas, urutan indeks baru dikirim ke `PATCH /program/{program}/urutan-gerakan` (`reorderExercises()` memvalidasi urutan adalah permutasi lengkap indeks sesi) dan tersimpan permanen ke `exercises_json`; modal dirender ulang dari data terbaru. Bila pustaka SortableJS gagal dimuat, daftar tetap tampil normal, hanya tidak bisa diseret.
- **Hapus Gerakan** (tombol tong sampah di tiap baris gerakan): konfirmasi lewat `confirmModal()`, lalu `DELETE /program/{program}/gerakan/{index}` menghapus entri itu saja dari `exercises_json` (diindeks ulang). Gerakan terakhir dalam satu sesi tidak boleh dihapus (satu sesi minimal 1 gerakan, balas 422).
- **Tambah Gerakan** (tombol di bawah tiap sesi): membuka modal `#addExerciseModal`, pelatih memilih area otot (chip) lalu memilih dari daftar pustaka area itu (`POST /gerakan/alternatif-area` → `AiWorkoutService::alternativesForArea()`, dikurangi gerakan yang sudah ada di sesi) atau membuat 1 gerakan baru dengan AI (`POST /gerakan/generate-area` → `generateForArea()`). Pilihan dikirim ke `POST /program/{program}/gerakan` (`appendExercise()`), divalidasi ulang dengan `validateReplacement()` + cek dobel nama, lalu ditambahkan di akhir sesi. Modal dirender ulang dari data terbaru seperti pada Ganti Gerakan.
- **Opsi AI di modal yang sama**: tombol "Buatkan gerakan baru dengan AI" memanggil `POST /program/{program}/gerakan/{index}/alternatif-ai` → `AiWorkoutService::generateReplacement()` meminta Gemini TEPAT SATU gerakan baru (otot sama, wajib beralat dari daftar, beda dari isi sesi + nama yang sudah ditawarkan lewat `exclude`; suhu 0.9 agar variatif, bisa diketuk berulang untuk variasi lain). Hasil lolos `validateReplacement()` (saringan alat/bodyweight/pemanasan yang sama) lalu tampil sebagai pilihan berlabel "Baru dari AI"; memilihnya mengirim `PATCH` dengan payload `exercise` utuh, yang divalidasi ulang di server (`validateReplacement()` + cek dobel nama di sesi) sebelum ditukar. Bila Gemini gagal/tidak aktif, endpoint membalas 422 dan UI menampilkan pesan, daftar pustaka tetap bisa dipakai.

### 3f. History sesi (`#historyModal`, `ClientController@history`)
Dimuat saat modal dibuka via `GET /klien/{id}/riwayat` (tidak membebani halaman daftar). Respons JSON: `name, total, remaining, first, last, sessions[]`.
- Ringkasan atas: **Sesi selesai**, **Sisa paket**, tanggal latihan pertama → terakhir.
- Hanya `status = completed`, urut **terbaru → terlama** (kalkulasi selisih beban dilakukan urut lama → baru).
- Tiap sesi: tanggal (`translatedFormat('l, d F Y')`), jam mulai, durasi, label program, daftar gerakan dengan nama, alat, **set × repetisi aktual** (`sets_label`, mis. "4 set x 10 reps") + beban riil (kg, untuk sesi per-set = top set), baris ringkas per set (`detail_label`) bila sesi memakai format per-set, **selisih beban vs sesi sebelumnya** untuk gerakan sama (▲ hijau / ▼ oranye, dibandingkan dari top set), `coach_note`, dan tombol **"Lihat Kartu IG Story 📸"** (jika ada `share_token`) → `/progress/{token}` di tab baru (`target="_blank"`, `data-turbo="false"`).
- Kosong → "Belum ada riwayat sesi selesai untuk klien ini. Yuk mulai sesi pertamanya dari Kalender! 🌸".

## 4. Generator program AI (`AiWorkoutService`)

- `generate(array $client): array{programs, source}` — `source` = `'ai'` atau `'template'`.
- **Gemini**: aktif bila `GEMINI_API_KEY` terisi. `POST https://generativelanguage.googleapis.com/v1beta/models/{GEMINI_MODEL}:generateContent` dengan header `x-goog-api-key`, `systemInstruction` (aturan + daftar alat), `responseMimeType: application/json`, timeout 40 dtk. Prompt memuat gender, umur, berat, tinggi, tujuan (ditambah `goal_note` bila terisi), **seluruh array fokus tubuh** (AI diminta membagi area secara seimbang antar sesi dan mencantumkannya di `day_label`), frekuensi, catatan.
- Jumlah sesi = `pt_frequency_per_week` (2x → Sesi A & B). **Gerakan per sesi: minimal 5, maksimal 6 gerakan utama** (`AiWorkoutService::minExercises()`/`maxExercises()`); khusus fokus tunggal "Seluruh Tubuh" dengan frekuensi 1x/minggu: **minimal 6, maksimal 7**. Pemanasan (jalan cepat, treadmill, sepeda statis, elliptical, peregangan) **bukan gerakan**: dilarang masuk daftar (prompt AI melarangnya, hasil AI disaring namanya, template tidak membuatnya). Hasil AI dipotong ke maksimal; sesi AI yang kurang dari minimal **dilengkapi otomatis dari template fallback** di `generate()`.
- **Semua gerakan WAJIB beralat** (keputusan Irgi 2026-11-23: ke gym ya memakai alat gym). Prompt Gemini melarang gerakan bodyweight secara eksplisit; hasil AI disaring `matchedEquipment()`: gerakan dibuang bila nama termasuk bodyweight murni (plank, push up, superman, burpee, sit up, dead bug, dll), alatnya "Tanpa Alat", atau alatnya tidak cocok dengan satu pun nama di daftar alat tersedia; alat yang tersimpan adalah nama resmi dari daftar (agar ikon foto alat cocok). Daftar alat kosong = tidak ada program yang bisa dibuat.
- **Fallback template** (`fallback()`): dipakai bila key kosong / API gagal / respons tak valid. Memakai pustaka gerakan per area (Bokong, Kaki & Paha, Dada, Punggung, Lengan & Bahu, Perut & Pinggang, Seluruh Tubuh), membagi area fokus bergiliran ke tiap sesi, semua slot adalah gerakan utama (tanpa pemanasan) sejumlah minimal yang berlaku; gerakan yang alatnya tidak ada **dilewati** (tidak ada pengganti bodyweight), lalu sesi dilengkapi sampai jumlah minimal dari pustaka Seluruh Tubuh + Perut & Pinggang. Beban awal wanita = 0,6× pengali.

## 5. Kalender & live session (`/`, `calendar.blade.php`, `ScheduleController`)

**Kalender**: grid bulan penuh (minggu mulai Senin), tombol `<` `>`; titik **pink** = ada jadwal belum selesai, titik **hijau** = ada yang `completed`. Ketuk tanggal → agenda + **+ Tambah Jadwal**. Data lewat `GET /jadwal?month=YYYY-MM` (satu request ringan; **tanpa request eksternal** — fitur hari libur sengaja dibatalkan karena memberatkan).

**Tambah jadwal**: pilih klien, program (default otomatis), tanggal, jam. **Aturan sisa sesi** (`ScheduleController@store`, dalam transaksi dengan `lockForUpdate` pada klien):
1. `remaining_sessions <= 0` → ditolak (422): *"Sisa sesi klien ini sudah habis (0). Silakan perpanjang paket sesi di menu Klien terlebih dahulu."*
2. Jumlah jadwal klien berstatus `scheduled` (sudah dibooking, belum selesai) `>= remaining_sessions` → ditolak: *"Sisa sesi klien ini (N) sudah terpakai semua oleh jadwal yang sudah dibuat. Selesaikan atau hapus jadwal lama, atau perpanjang paket sesi di menu Klien."* (karena tiap sesi selesai mengurangi 1 sisa, booking tidak boleh melebihi sisa; jadwal lama yang tidak pernah diselesaikan ikut terhitung — hapus bila tidak jadi).

## 6. Integrasi GoWA (`GowaWhatsappService`)

- Konfigurasi: `GOWA_BASE_URL`, `GOWA_USERNAME`, `GOWA_PASSWORD` (Basic Auth bila username terisi), opsional `GOWA_DEVICE_ID` → header `X-Device-Id` (GoWA multi-device).
- **Badge status** (kanan atas): `WA Aktif` (`bg-success-subtle text-success`) / `WA Tidak Aktif` (`bg-danger-subtle text-danger`) / `Cek WA...` (abu, belum dicek).
  - `cachedStatus()`: dibaca dari cache saja (tanpa HTTP) → dipakai saat render halaman lewat View composer (`$waState`). Tidak dikonfigurasi → `false`.
  - `checkStatus()`: `GET {base}/app/devices` (timeout 4 dtk), **di-cache 120 detik**; aktif hanya bila device sendiri (`GOWA_DEVICE_ID`) ada di hasil DAN `jid`-nya terisi. Perhatian: instance GoWA di `wa.iconix.id` dipakai bersama banyak tenant, endpoint ini mengembalikan device semua tenant, jadi JANGAN menilai aktif dari jumlah hasil (bug lama: badge selalu hijau). `jid` kosong berarti device terdaftar tapi belum di-scan/link. Dipanggil hanya dari endpoint `GET /wa-status`.
  - Browser: `public/js/app.js` mengecek `/wa-status` saat badge berstatus `checking` dan polling tiap 60 dtk. Header bersifat `data-turbo-permanent` sehingga badge tidak dirender ulang tiap pindah menu.
- **Kirim pesan** `sendMessage()`: `POST {base}/send/message` JSON `{phone: "62…@s.whatsapp.net", message}`; nomor dinormalisasi (`08…` → `628…`); semua error ditangkap → `false`.
- **Format laporan** (`buildSessionReport()`), urutan:
  1. Sapaan: "Halo kak {nama depan}! 💖" + terima kasih.
  2. *Ringkasan Sesi*: program, durasi (menit), sisa paket.
  3. *Catatan dari Coach Neil 📝* (jika ada).
  4. *Pengingat Nutrisi 🥗*: rentang `min g – max g per hari` (batas minimal & target optimal) + saran porsi pasca-latihan (30% target optimal).
  5. *Tips Pemulihan 😴* + kalimat motivasi penutup.
  6. Bila ada `share_token`: blok kartu progres (`📸 *Kartu Progres Mu:*`, kalimat pengantar, lalu **URL di baris baru**: `url('/progress/{token}')`).
  7. Footer `_- Gym Tracker by Neil_`.
  - **Rincian gerakan SENGAJA tidak ada di WA** (dulu ada bagian *Pencapaian Gerakan Hari Ini*): sejak live session mencatat per set, daftar itu membuat WA kepanjangan. Detail gerakan (termasuk per set) hidup di kartu progres dan History.
- **`APP_URL` harus URL publik** agar link kartu progres bisa dibuka klien.
